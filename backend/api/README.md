# CounterGuard API Layer

This module defines the RESTful application interfaces for CounterGuard using **FastAPI** and **Pydantic v2**, structured around **Clean Architecture** principles.

## Endpoints Description (`/api/v1` prefix)

### 1. Core Investigation Engine (`routes/investigation.py`)
- **`POST /api/v1/investigate`**: Initiates a synchronous multi-agent evaluation on a provided product listing URL. Returns an immediate `InvestigationReport` generated by the LangGraph orchestrator and specialist AI agents.

### 2. Investigation History API (`routes/investigations.py`)
Exposes persistent records stored in SQLite/PostgreSQL (from Task 1 storage repository layer) without coupling API handlers directly to ORM mechanics.
- **`GET /api/v1/investigations`**: Retrieves a paginated list of investigations.
  - Query Parameters:
    - `page` (int, default=1)
    - `page_size` (int, default=20)
    - `marketplace` (Optional[str]) - Case-insensitive filter
    - `status` (Optional[str]) - Case-insensitive filter
    - `sort_by` (str, default='created_at')
    - `sort_order` (str, default='desc' or 'asc')
  - Returns `InvestigationListResponse` (including enriched summary badges like `product`, `risk_level`, and `risk_score`).
- **`GET /api/v1/investigations/{id}`**: Returns an `InvestigationDetailResponse` containing metadata, full multi-agent `evidence_timeline`, and the complete synthesized `report`. Returns HTTP 404 if the record does not exist.
- **`DELETE /api/v1/investigations/{id}`**: Deletes an investigation entity, cleanly cascading removal to all child reports and evidence timeline entries. Returns HTTP 404 if not found.

## Clean Architecture Integration
- Route controllers rely solely on FastAPI Dependency Injection (`Depends(get_history_service)`) to instantiate the `InvestigationHistoryService`.
- Database sessions are scoped via `get_db_session()`, providing automated rollback protection and straightforward testability via SQLite in-memory overrides.
